# 配布スクリプトの仕様

この文書は、`codex-account-switcher` プロジェクトのソースから
`codex-switch` という単一の CLI 実行ファイルを作り、利用者の
ローカル配置先へ安全に置くためのスクリプト仕様を定める。公式アプリ、公式アプリに
同梱される Codex、GUI、画像、その他のバイナリは配布対象にしない。

## 成果物の境界

`Package.swift` が定める Swift 6・macOS 14 以降の実行ファイル
`codex-switch` だけをビルドする。`scripts/build.sh` は Release 構成で
`swift build --configuration release --product codex-switch` を実行し、既定では
`dist/codex-switch` を作る。開発者は Swift 6、macOS 14 以降、Git、および
`scripts/check-distribution.sh` が要求する PCRE2 対応の `rg` を用意する。

ビルドしたファイルは出力先と同じディレクトリに一時配置し、実行権限を確認してから
`codesign --force --sign -` で ad-hoc 署名する。`codesign --verify --strict` が成功した
後に原子的な `mv` を行うため、検証前のファイルを既存の出力へ置かない。開発者証明書と
notarization はこのローカルビルドに必要ない。`dist` は作業用の生成先であり、Git に
バイナリを追加しない。

## インストール

`scripts/install.sh` は既定で `dist/codex-switch` を
`~/.local/bin/codex-switch` にインストールする。`--source` と `--destination` を
指定すれば、別の入力と一時配置先で同じ処理を実行できる。

処理は次の順序で行う。

1. 入力がシンボリックリンクでない、実行可能な通常ファイルであることを確認する。
2. 配置先の親ディレクトリと、その途中のディレクトリにシンボリックリンクがないことを確認する。
3. 親ディレクトリ内に専用のロックと段階配置用ディレクトリを作る。
4. 既存の実行可能な配置先を一意な `.codex-switch-backup.*` ディレクトリへ移す。
   既存のバックアップは上書きしない。シンボリックリンク、ディレクトリ、実行権限の
   ないファイルは、利用者所有の別ファイルを置き換えないため拒否する。
5. 同じ親ディレクトリ内の段階配置ファイルを `mv` で配置先へ移す。
6. 配置先が通常の実行可能ファイルであることを読み取って確認する。

入力、段階配置ファイル、配置後のファイルはバイト列が一致することを比較し、macOS の
`codesign --verify --strict` でも署名を確認する。インストールとアンインストールは同じ
配置先ロックを使うため、対象の入れ替えと移動が同時に走らない。

段階配置または確認に失敗した場合、既存の CLI を退避先から元の配置先へ戻す。失敗した
新しいファイルを削除して結果を隠すのではなく、調査できる `.codex-switch-failed.*`
退避先へ移す。実際の認証、Keychain、共有ホーム、履歴、設定、MCP はこのスクリプトの
対象外であり、インストール処理で変更しない。段階配置中に SIGINT や SIGTERM を受けた
場合も、既存の CLI を復元して中断した終了ステータスを返す。SIGKILL の場合はシェルが
後始末できないため、`.codex-switch-backup.*` が残ることがある。配置先がないことを
確認してから、そのディレクトリ内の `codex-switch` を元の配置先へ `mv` すれば復元
できる。バックアップを上書き・削除せず、復元前に内容を確認する。

## アンインストール

`scripts/uninstall.sh` は既定の配置先、または `--destination` で指定した 1 個の
CLI 実行ファイルだけを対象にする。既定では対話的な確認を要求し、明示的に `--yes` を
指定した自動処理だけが確認を省略できる。シンボリックリンク、ディレクトリ、実行権限の
ない通常ファイルは移動しない。

削除の代わりに、対象ファイルを一意な `.codex-switch-removed.*` 退避先へ移す。これに
より、誤操作時もファイルを戻せる。認証ファイル、state v2、登録用の回復可能な資格情報、
Keychain 項目、公式アプリ、その他のユーザーファイルは読み書きも削除もしない。

## 公開前の確認

`scripts/check.sh` が、Swift テスト、Release CLI ビルド、全配布スクリプトの構文確認を
行った後、`scripts/check-distribution.sh` を呼び出す。後者は Swift を起動せず、直接
実行しても同じ公開スキャンと一時領域のライフサイクル検証を行える。公開対象の一覧は
`git ls-files --cached --others --exclude-standard` で取得し、Git 管理前の新規ファイルも
含める。`.git` と Git 管理下にない `.build`・`dist` の生成物は除外するが、Git 管理下の
同じ場所にあるファイルは除外しない。

内容検査では、秘密鍵、JWT 形式の値、代表的なプロバイダー API トークン、長い秘密値の
代入、個人のメールアドレス、個人の絶対パス、非テキストのバイナリを検出する。公開対象
のファイルに合成値用の例外やマーカーはなく、テスト用の値は実行時に隔離した一時
ディレクトリで検出器ごとに生成する。スキャンは既知の形式を見つけるための補助的な
ヒューリスティックであり、秘密情報がないことを保証しないため、公開前に人が内容を
確認する。

この確認は実アカウント、ネットワーク、実 Keychain、公式アプリ、インストール先の
`HOME` を使わない。ブラウザー認証、Keychain の再許可、アプリ内ターミナルの操作は
[手動受け入れ確認](manual-acceptance.md) で別に行う。
