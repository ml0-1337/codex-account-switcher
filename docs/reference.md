# コマンドとデータの仕様

基本操作は [README](../README.md#使い方)を参照してください。
ここでは認証情報の扱い、復旧、既存バージョンとの互換性を説明します。

## コマンド

| コマンド | 動作 |
| --- | --- |
| `codex-switch` | 登録済みアカウントを選び、共有認証ファイルを切り替えます。 |
| `codex-switch setup` | 現在のアカウントを初回登録します。 |
| `codex-switch add` | ブラウザーでログインし、別のアカウントを追加します。 |
| `codex-switch list` | 登録済みアカウントと、最後に切替指定したアカウントを表示します。 |
| `codex-switch recover` | 中断された操作や管理情報の不整合を復旧します。 |
| `codex-switch help` | ヘルプを表示します。`-h` と `--help` も使えます。 |

引数なしの切り替え、`setup`、`add`、`recover` は対話端末で実行します。
未知のコマンドや余分な引数は終了コード `2` で拒否します。
`--no-restart`、`switch`、`doctor`、`restart` は提供していません。

## setup

現在の `~/.codex/auth.json` を、最初の切り替え候補として Keychain に保存します。
通常の登録済み状態では既存の登録を表示して終了し、認証情報の再保存や公式 Codex の起動は行いません。
未完了の記録や状態の不整合がある場合は停止します。

初回登録では、公式アプリにログイン済みで、共有の `auth.json` が必要です。
`~/.codex/config.toml` のトップレベルに `cli_auth_credentials_store = "file"` を設定してください。
`keyring`、`auto`、未設定など、ファイル方式を確認できない場合は案内を表示して停止します。
ツールが普段の設定を書き換えることはありません。

登録時は、署名を検証した公式アプリの同梱 Codex を子プロセスとして起動します。
app-server の読み取り専用 API で設定とアカウント情報を確認し、`account/read` には
トークン更新を要求しない `refreshToken: false` を指定します。この指定だけで、公式側の再認証や
通信が絶対に発生しないことを保証するものではありません。[App Server の認証仕様](https://learn.chatgpt.com/docs/app-server)も参照してください。

確認後、既存の認証ファイルのバイト列をそのまま Keychain に保存し、読み戻して照合します。
表示名、プロファイルの識別子、作成日時などはツールの `state.json` に保存します。
登録の途中経過はジャーナルに記録し、正常に完了したら取り除きます。

`setup` 自体は共有の `auth.json` や `config.toml` を書き換えません。
アカウント情報の確認中に `auth.json` が変わった場合は、登録を中止します。
認証や設定の確認に失敗した場合も、登録完了として扱いません。

## add

署名を検証した公式アプリの同梱 Codex を使い、新しいアカウントでログインします。
端末に表示されるデバイスコード用の URL とコードを、本人がブラウザーで操作します。

ログインは専用の一時 `CODEX_HOME` で行い、その一時ホームにだけファイル認証の設定を作ります。
共有ホームの履歴、通常の設定、MCP 構成はコピー・変更せず、普段の `CODEX_HOME` も変更しません。
追加が完了しても、共有認証や現在の選択は切り替わりません。

同じメールアドレスの別アカウントは、表示名の末尾に短い識別子を付けて区別します。
同じアカウント ID の二重登録は拒否します。
一時ホームの削除に失敗した場合は、表示された案内に従ってください。
ログイン用の URL・コードや残った一時パスを、公開するログへ貼り付けないでください。

## list

登録済みの表示名と、最後に選択したプロファイルを示すマーカーを表示します。
マーカーはツールの管理情報であり、起動中の公式アプリが実際に使うアカウントを示すものではありません。
状態は変更せず、サーバーの利用状況や認証の有効性も問い合わせません。

## 切り替えと完了条件

実行中のタスクをすべて完了してから、引数なしの `codex-switch` を実行します。
通常の切り替えは共有ファイルと Keychain を使い、Codex の起動やネットワーク通信を行いません。
必要な認証情報が登録済みなら、公式アプリがインストールされていなくても切り替えられます。

成功表示は、対象の認証ファイルを書き込み、ローカルのファイルと Keychain を読み戻して検証したことを意味します。
サーバー上の認証の有効性や、実行中のアプリへの反映までは示しません。
別のプロセスが後から共有認証を書き換える場合もあります。

切り替え後は公式アプリを手動で再起動し、アカウント表示を確認してください。
ツールは公式アプリの終了・起動・変更・通知を行いません。

## recover

未完了の記録や管理情報の不整合があり、CLI が復旧を案内した場合に実行します。
保留記録を手動で編集・削除したり、古い認証ファイルをコピーして戻したりしないでください。

```sh
codex-switch recover
```

確認に `y` と答えると、現在の認証に合わせて管理情報と Keychain のレコードを整合させます。
共有の `auth.json` を修復・書き換える処理ではありません。
ネットワーク通信や公式アプリの操作も行いません。

登録途中の復旧は、保存がどこまで終わったかによって変わります。

| 中断した状態 | 復旧時の動作 |
| --- | --- |
| Keychain への保存が完了している | 保存済みの認証を削除せず、登録を完了します。 |
| `setup` の Keychain 保存前 | 共有認証が登録記録と一致することを確認して、登録を再開します。 |
| `add` の Keychain 保存前 | 共有認証と管理情報を確認し、準備記録だけを取り消します。追加には `add` の再実行が必要です。 |

保存済みと記録された認証が見つからない場合や、共有認証が欠落・破損・対象不一致の場合は、記録を残して停止します。
元のアカウントに戻したい場合は、復旧後に通常の切り替えを行ってください。

切り替えジャーナルは v3、登録ジャーナルは v2 を使います。
古い形式の保留記録を新しい形式として解釈せず、案内に従って旧バージョンで操作を完了してから再実行します。

## 保存先と互換性

公式の ChatGPT / Codex デスクトップアプリとローカルの Codex CLI が使う、共通の `~/.codex` を利用します。
履歴、設定、MCP 構成をアカウントごとに複製しません。
ChatGPT Web やクラウドタスクをアカウント間で引き継ぐ機能はありません。

ツールの管理情報は次のディレクトリに保存します。

```text
~/Library/Application Support/Codex Account Switcher
```

既存の state v2 と Keychain レコード v1 を引き継ぎます。
Keychain サービス名は `app.codex-account-switcher.credentials.v1`、項目キーはプロファイルの UUID、
ラベルは `Codex Account Switcher — email` です。

以前の GUI を保持している場合は、CLI と同時に操作しないでください。
既存の Keychain 項目へのアクセスや、ad-hoc 署名の更新後に、macOS が許可を求める場合があります。
拒否された操作を成功扱いにしたり、アクセス制御を迂回したりはしません。

ファイル認証とその他の保存方式については、[認証情報の保存仕様](https://learn.chatgpt.com/docs/auth)を参照してください。
外部仕様の記載は2026年9月8日に確認した内容に基づきます。

## 公式アプリの確認

初回 `setup` と `add` は、公式アプリと同梱 Codex の両方について署名を検証します。
Apple 発行の証明書と公式 Team ID を確認した後で、同梱 Codex を実行します。
これらの確認は必要な操作に限って行い、通常の切り替えや `recover` では公式 Codex を起動しません。
公式アプリ、同梱 Codex、GUI、画像などは、このプロジェクトの配布物に含めていません。

## 終了コード

| コード | 意味 |
| ---: | --- |
| `0` | 処理が完了しました。`list` と `help` も含みます。 |
| `1` | 認証、ファイル、Keychain、設定、対話入出力、復旧などの処理に失敗しました。 |
| `2` | コマンドまたは引数が不正です。 |
| `130` | No、空入力、EOF、`q`、Ctrl-C などによるキャンセルです。 |
| `143` | SIGTERM による中断です。 |

終了コードだけでなく、成功表示と選択先を確認してください。
実機で詳しく確認する場合は、[手動受け入れ確認](manual-acceptance.md)に従ってください。
